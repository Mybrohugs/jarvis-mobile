# Видео на ТВ — мобильная DEV-копия

Ветка dev/home-assistant-video, база main. PR #2 не применён. Итоговый DEV-пакет подготовлен в релизе v1.4.
Форма отправляет «на телевизор <URL>» через существующий pc.say → /api/say.
Нужны paired-компьютер, приватный HTTPS-доступ через Tailscale, разрешённый
origin этой PWA и работающий PhoneExecutor с DEV-кодом.
Телефон не получает секреты Home Assistant или YouTube.

Меню «Поделиться» лишь заполняет поле. Отправка — только по кнопке «На ТВ».
После одного POST форма до 60 секунд получает результат своего запроса через
GET /api/queue. Ошибка связи или неизвестный статус не запускает повторный POST.
Отказ ТВ отображается как ошибка; ожидание не считается воспроизведением.
Точное подтверждение YouTube делает ПК: совпадение videoId и playing.
Другие сайты зависят от поддержки исполнителем ПК.

Проверки:

    node --test tests/tv.test.cjs tests/tv-ui.test.cjs tests/pc-queue.test.cjs
    node --check main.js
    node --check pc.js
    node --check tv.js
    git diff --check

Итоговая проверка: Node 24 PASS. Сквозная браузерная проверка 390x844 с настоящими HTTP-шлюзом,
очередью и исполнителем: PASS, один POST, GET очереди, итог на форме, без ошибок JS.
В этом браузерном тесте ТВ и посторонний AI SDK подменены; реальное воспроизведение
ролика 5-wdT_xbVDQ и его ID/playing проверены отдельно на ПК.
Тестовый скрипт: coding-agent/scripts/check_tv_mobile_dev.py.
Снимок: tests/tv-mobile-preview.png. Пользователь подтвердил передачу видео с телефона на ТВ 31.10.2026.

Для локального просмотра:

    python -m http.server 10796 --bind 127.0.0.1

Loopback-просмотр не заменяет приватный HTTPS-доступ с настоящего телефона.
Production, настройки действующего шлюза и опубликованная PWA не менялись.

## Отдельный приватный запуск на телефоне

DEV-сервис поднят отдельно на HTTPS-порту 8443, действующий 443 не менялся.
Включите Tailscale и используйте DEV-ссылку, выданную в чате. Код подключения
введите прямо в TV-форме. Он одноразовый и действует 10 минут.
Ключ Claude не требуется: tv_ui.js и pairing не зависят от облачного SDK.
Этот DEV-origin предназначен только для проверки видео; остальные возможности
мобильного приложения здесь не обслуживаются. Данные и очередь изолированы.
Поддержка :8443 добавлена только в этой DEV-копии. Публикации на GitHub Pages нет.

Node-команда теперь включает tests/tv-pair-ui.test.cjs: всего 11 PASS.
Проверка реального HTTPS и запрета неавторизованного чтения очереди: PASS.
Изолированный сервис: coding-agent/developer_core/jarvis_local/tv_phone_dev.py.
Остановка приватного DEV-порта: tailscale serve --https=8443 off.

Pairing дополнительно проверяет сохранение pcUrl и ключа после записи. Если хранилище браузера отказало, успех не показывается. Повторная загрузка страницы с сохранённым ключом не требует кода. Всего 14 мобильных тестов PASS. Другой origin (включая порт), браузер или отдельный контекст приложения требует своей привязки.

Для исключения сохранённого адреса другого экземпляра добавлена отдельная /connect.html с connect.js/connect.css. Она отправляет код только текущему origin. Проверено реальное HTTPS-сопряжение в браузере и reload без кода; тестовая привязка после проверки удалена отдельно. Всего 16 Node-тестов PASS.

Ссылка /connect.html#code=<одноразовый-код> только заполняет поле и удаляет fragment из адресной строки; POST выполняется по кнопке. Код/ключ не пишутся в диагностику. DEV pairing-events.jsonl содержит только время, тип события и HTTP-статус. Проверки: 17 Node PASS; настоящее HTTPS-заполнение без POST PASS.
